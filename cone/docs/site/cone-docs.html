Visão geral

pt-BR

Cone é a plataforma de gestão de treinos do coach: programação estruturada de sessões, páginas públicas para os atletas (agenda, resultados, perfil, ranking), operação de aula ao vivo com TV na parede, e a gestão do negócio do coach (locais, valores, agenda). Funciona hoje em produção no Team Medrado.

Arquitetura em uma linha: Vite + React 19 no front; Supabase (Postgres com RLS, Realtime, Auth por código OTP) no back; deploy estático no GitHub Pages. Atletas usam as páginas públicas sem login; o coach autentica com código de 8 dígitos por e-mail. Escritas anônimas passam somente por funções seguras (check-in e registro de resultado) — endurecido e verificado ponta a ponta.
Estado atual: funcionalidades completas em relação ao plano original — tudo que está em andamento é extra. O próximo ciclo é o programa de design (10 sessões que refinam cada superfície e preparam o app para os novos temas), e este documento apoia a definição de tiers junto ao coach.

Personas & Serviços

pt-BR

🏋️ Coach (solo) · usuário principal hoje

Dono de tudo: programa as sessões, roda a aula ao vivo (Quadro + TV), registra e revisa resultados, gerencia atletas/PRs/metas, exporta a grade e acompanha o próprio negócio (locais, valores/hora, Pix, agenda). Autenticado por código OTP + lista de permissão.

🤸 Atleta · sem login (por enquanto)

Aluno regular. Consome a agenda e o hub do dia, faz auto-registro de resultados, acompanha PRs/metas/perfil, aparece nos rankings e faz check-in na aula. Identidade hoje = cadastro feito pelo coach + seleção no aparelho; muda quando o acesso por atleta (#30/#31) for construído.

👋 Convidado / drop-in

Chega, escaneia o QR da TV, faz check-in digitando o nome e tem resultado só naquele dia (de propósito — sem rastro permanente). Caminho de conversão: o coach cadastra como atleta.

🏢 Box (dono / multi-coach) · futuro

O que muda em relação ao coach solo: várias contas de coach, identidade de atleta + reservas de aula (#40), marca própria (o tema "Common" neutro é a cara amigável para boxes) e separação por local — o modelo de locais já existe na aba Serviços.

Os 5 pacotes de serviço que o produto entrega

1 · Programação

Construção estruturada de sessões: 12 tipos de bloco, estações, complexos, intensidade por gênero/%/progressão, registro com cargas-padrão. O modelo de dados é o diferencial — os concorrentes usam texto livre.

2 · Publicação

Páginas públicas para os atletas + grade exportável/impressa (Publicador) + controle de visibilidade por sessão.

3 · Aula ao vivo

Check-in por QR, ficha da turma, registro ao vivo, TV na parede com timer/ranking/rotação. É o equivalente do "whiteboard" do SugarWOD.

4 · Desempenho

Resultados, PRs, metas, taxa RX, rankings, perfil por atleta — e no futuro adaptações por atleta (#39) e gráficos de progressão.

5 · Negócio do coach

Locais + valores/hora, Pix, calendário de aulas e personal, relatório de conclusão. Invisível para o atleta.

Tiers — quadro interativo

Ferramenta para a conversa: cada carta é uma funcionalidade "gateável". Clique para circular entre Livre → Pro → Box. Ao final, Exportar gera a tabela em markdown para voltar ao PRODUCT.md.

Princípios combinados: o tier Livre continua sendo uma ferramenta genuinamente usável para um coach solo (programação + publicação + registro nunca são pagos); os gates ficam na alavancagem operacional (TV, exports, negócio, análises) — nunca no acesso do atleta aos próprios dados.
Sempre no Livre (núcleo, fora do quadro): criador de sessões · publicação/agenda pública · hub do dia · timer · auto-registro e check-in · leaderboard básico · perfil/PRs do atleta · cadastro de atletas · registro de exercícios · backup de estado.

Design benchmark

EN · full report: docs/reviews/2026-07-09-design-benchmark.md · click a screenshot to zoom

Every surface driven live at 1280×800 and 390×844 (2026-07-09; screenshots re-taken 2026-07-10), compared against SugarWOD / Wodify / BTWB / PushPress. Severity: 🔴 high · 🟡 medium · ⚪ low.

Market read

AppOwnsRelevant patterns
SugarWODCommunity / whiteboard standardToday's-WOD-first mobile UX, live TV leaderboard during class, fist-bumps/comments, auto-PR celebration
WodifyCoach programmingVisibility scheduling, embedded demo videos, coach notes, programming marketplace
BTWBAnalytics depth1500+ benchmark library, per-movement progression charts, global leaderboards (dated UI)
PushPressGym operationsOne-tap booking/waitlist/check-in, push reminders, member self-service

Cone's standing: the structured data model (load × distance × intensity, per-gender Rx/Inter/SC) exceeds all four — they model movements as free text. The two market patterns Cone lacks: the community loop (needs athlete identity) and BTWB-style progression charts (needs no new data — everything is already in results/PRs).

Cross-cutting (every session applies)

  • 🟡 Icon language split: emoji in public nav + SPA sidebar vs Tabler icons everywhere else — decide once, apply per page.
  • 🟡 SPA button-style zoo (filled cyan / outlined blue/red / chips) — C0 defines primary/secondary/destructive/ghost from tokens.
  • 🟡 Confirm-modal policy inconsistent: results.html confirms a self-log, schedule.html doesn't; destructive "Limpar estado" has no friction at all.
  • ⚪ SPA fires ~14 doomed write requests (401) before login on every cold load — suppress-until-auth candidate.

Design program

EN · umbrella: docs/plans/16-design-pass-program.md · backlog rows #49–#59

One session per bundle; each folds in that surface's token sweep (#15), mechanical accessibility (#14) and fixed-height layout (#18), so no page is touched twice. The program ends with a token-clean codebase — the prerequisite for the new "Common" + Halo themes (#43), which is what lets Cone be shown beyond the current gym.

Mobile — Android / iOS

EN · full assessment: docs/MOBILE.md
Standing: Cone is already ~60% of a PWA. A complete manifest.json (standalone display, icons, app shortcuts) is linked from every public page, and index.html ships a custom in-theme install banner. Installable on Android today from GitHub Pages; iOS works via Add-to-Home-Screen (manual). The only missing piece is a service worker (offline, precache, and a fix for the chunk-hash-404 pain). Recommendation: do nothing now — single coach, single box for 6+ months.

1 · Finish the PWA · S/M — only near-term-worthy step

vite-plugin-pwa service worker; installed-app feel, faster loads on gym Wi-Fi, substantially fixes chunk-hash 404s. Do #29 (Vercel) first — it makes this materially easier.

2 · Play Store via TWA · S on top of path 1

Bubblewrap wraps the finished PWA. Google Play account: $25 one-time. Android only. Store presence without touching app code.

3 · Capacitor (iOS) · M/L — only if the App Store becomes a business need

Apple Developer $99/yr + macOS/Xcode build (you're on Windows → Mac or cloud build). Real review risk: guideline 4.2 rejects thin wrappers. Note: iOS 16.4+ supports web push for installed PWAs — reminders may not need this at all.

4 · React Native rewrite · rejected

A full client rewrite to escape a WebView the product doesn't suffer from. Not justified at any foreseeable scale.
