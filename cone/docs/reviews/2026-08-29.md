## High

**H1 · Three of the Atletas grade's four signals are structurally dead on real data.**
`public/lib/sessions.js:34-41` — `matchesAthlete(s, name)` is true only when `s.mainTraining`
contains the athlete's **name**. **Every one of the 55 sessions in the last 30 days of the prod
snapshot has no `mainTraining` at all** (measured: the field is absent on 55/55). The app's real
sessions are gym-wide, not per-athlete, so every consumer defined as "sessions assigned to this
athlete" resolves to zero. Three symptoms, all confirmed live on the same screen:

- `atletas/atletasHelpers.js:239-261` `adherence()` → `calcBlockStats` returns `planned = 0` →
  returns `null` → **ADERÊNCIA renders `—` on 100% of cards**, including athletes with a logged
  result two days ago (80 `results_v2` rows exist, newest 2026-08-27).
- `atletas/atletasHelpers.js:329-340` `presenceCellState()` returns `'none'` for **all 28 cells** →
  Presença · 4 semanas is a blank slab whose legend advertises two states it never shows.
- `SessionStrip` lists sessions from **16–17/07** on a card whose own "últ. sessão" reads **2 d** —
  two contradictory notions of "this athlete's session" (assignment-derived vs results-derived) side
  by side.

⚠️ **Not a #160 regression** — `calcBlockStats` was promoted from `me/meHelpers.js` with this
definition intact, so me.html's adherence bars have been equally empty. #160 gave it a prominent new
surface, which is what made it visible. → **#164**

**H2 · A paid invoice is still counted as money owed.** `afiliados/AffiliatesPane.jsx:199-207`
renders `<ReceivableRail>` with `locs`/`events`/`from`/`to` and **never passes `billing`**, so
`afiliados/ReceivableRail.jsx:29` sums `calcTotal(eventsForAffiliate(...))` for the month regardless
of invoice status. Driven end to end: Eagles' August advanced `open → draft → sent → paid` in
Fechamento, and "A receber · agosto" still reads **R$ 2.025** for Eagles with a grand total of
**R$ 2.025 + US$ 50**. The two panels of the same tab contradict each other. ⚠️ **A `sent` invoice
correctly stays** — it is still owed; the defect is `paid` only. #161 shipped `ReceivableRail`
_before_ #162 introduced the stamp, and #162 did not revisit it. → **#163**

## Medium

**M1 · The invoice board is one-way — a misclick is unrecoverable.** `afiliados/billingState.js`'s
`advance` moves only `open → draft → sent → paid`, and the `paid` detail renders **zero actions**
(confirmed live: status trail complete, no buttons). There is no revert, reopen, or correction path
short of editing the DB. 🔑 **The reducer already supports it** — `advance(stamp, 'draft')` returns
`{status:'draft'}` — so this is a missing UI affordance, not a model change. → **#165(a)**

**M2 · A paid invoice still renders a live, scannable Pix QR for the full amount.**
`afiliados/InvoiceDetail.jsx:115-119` keeps rendering the QR block after `paid`; screenshotted at 390
with "Agosto 2026 · Paga" directly above a valid R$ 2.025,00 code. Invites a second payment.
→ **#165(b)**

**M3 · `fmtMoney` is byte-identical in three sibling files.** `afiliados/InvoiceCard.jsx:22`,
`afiliados/InvoiceDetail.jsx:10`, `afiliados/MeuPerfilPane.jsx:13` — all three shipped in #162 on the
same day, and all three already import from `publicador/billing.js`, which is the canonical home
(pure, dependency-free, unit-tested, already exports `fmtDate`/`fmtDur`). Money formatting duplicated
across files is the exact shape that produced #104's four money bugs. → **#166**

**M4 · The presence grid has no cell-size cap, so a 4-week heatmap renders as a ~280px slab.**
`atletas/Atletas.module.css:374-376` — `.pgRow{grid-template-columns:repeat(7,1fr)}` +
`.pgCell{aspect-ratio:1}` with no `max-width`, inside the ficha's ~530px pane, computes to
**68.6 × 68.6px per cell** (measured live). The 9px day letters show the intended scale is a compact
calendar. Independent of H1: fixing the data would render 69px green blocks. → **#167**
