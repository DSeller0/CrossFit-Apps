# 2026-09-29 — gsd-core trial (#225): not adopted

[open-gsd/gsd-core](https://github.com/open-gsd/gsd-core) 1.14.0 was installed as a Claude Code
plugin in an isolated worktree and driven on one real row, #207, from `new-project` to `verify`.
The trial was **stopped at verify by decision**. The evidence below was enough, and the
remaining steps would have measured throughput, not the reasons it was declined. Full record,
with every number sourced: [plans/96](../plans/96-gsd-core-trial.md).

**Verdict.** Not adopted. gsd is a reasonable addition for a repo **without** a structured process:
it brings a discuss → plan → execute → verify loop, a code-review gate and a verify gate out of the
box. Cone already runs that loop (`BACKLOG.md`, `plans/NN`, the #223 must-haves gate,
`audit-backlog-markers.mjs`, `/app-review`), and gsd's version does not plug into it — it runs
**beside** it, at a fixed cost on every session.

---

## ✅ What it did better — lead with this

**It caught a real bug that everything else missed (CR-01).** `cone_athlete_filter` is one
localStorage key shared on purpose by `schedule.html`, `results.html` and `me.html`. The trial's
fix hardened `Schedule.jsx`; gsd's code review then grepped for every other
`setItem('cone_athlete_filter'` and found **`Results.jsx:151-154`** doing the byte-identical
unvalidated write, reachable through any `results.html?id=<anything>` because `Nav.jsx:84` carries
`?id=` across tabs. The verifier failed the requirement on it. The board row, the plan, the
requirements, gsd's own planner **and the session supervising the trial** had all traced `?id=`
through `Schedule.jsx` alone.

The native equivalent is precise: WORKFLOW.md requires `/code-review` only before pushing **M/L**
items, and #207 is **S** — so the written ritual would not have caught this before push. The
every-three-plans code review would have, a few plans later. The cheapest part of what gsd did — the
sibling grep — is now a plan-time rule (below).

Also credited in plans/96: the planner re-derived #207 sharper than the board row had it (an
*asymmetry* — `?athlete=` validated, `?id=` not — inside one function); `new-project` flagged, before
writing anything, that its `REQUIREMENTS.md`/`ROADMAP.md` would become a second board; the planner
found a third copy of the false #113 claim nobody else had; the verifier re-ran tests from disk
rather than trusting summaries, and reverted requirements the executors had marked complete before
verification ran.

## Why not

1. **The always-on cost has no supported floor.** `claude plugin details` reports ~10 700 tokens on
   every session — 144 skills (every capability ships twice, as command and skill) + 64 agents.
   gsd's own trimming tool, `/gsd-core:surface`, **cannot work in a plugin install**: its engine
   assumes the npm-global layout and has no plugin awareness, and Claude Code has no per-skill
   disable. A hand trim of the version-pinned cache reached ~7 008 — unsupported, invisible to the
   installer, silently undone by any update — and even that is above Cone's entire `CLAUDE.md` core
   (~6 500 after #224). The 64 agents are a floor no trim reaches.
2. **Its plans live outside Cone's consistency gate.** gsd writes `.planning/phases/`; #223's
   must-haves rule and `audit-backlog-markers.mjs` only see `docs/plans/`. Adopting means duplicating
   every plan or losing the gate built after #113 shipped broken.
3. **The summarising agents are confident and wrong at the joins.** The map's RLS section, an
   incomplete call-site table ("three others" — there were four), a config enabling four gates whose
   commands weren't installed. The planner-side agents were consistently good; the mapping and
   summarising ones were consistently not — and the plan-checker ran on the cheapest model.
4. **It is heavy to host.** Two global directories under `~/.claude` (five NTFS junctions, and the
   hand trim's quarantine), a **481 MB** plugin cache that neither `plugin uninstall` nor
   `marketplace remove` deletes, uncommitted runtime state (`.gsd/`, `.planning/state.json`,
   `milestone.lock`) left after its own commits, and a worktree pin that only holds when its tools
   run from the worktree root.

## Taken natively

- **WORKFLOW.md** — the *sibling sweep* (a fix for a bug class greps for every other instance; each
  is fixed or named deferred); *unfakeable* must-have wording ("fails visibly **and** writes
  nothing"); the every-three-plans code review, written down as the backstop for S items.
- **#207 → [plans/97](../plans/97-share-link-athlete-guard.md)** — port the trial's reviewed fix
  (`buildSessionShareUrl`, `findAthleteById`, 24 tests; applies cleanly to `main`) and close CR-01
  in `Results.jsx`. The `gsd-trial` branch is kept only until that port lands.
- **#226** — a row-length check in the board audit (the trial surfaced 13 rows over the cap).
- **Not taken:** a per-row `/code-review` before Done — the every-three-plans review covers it.

## Record

**Cleanup, 2026-09-29 — verified.** plans/96's own procedure had three bugs, fixed in the run:
uninstall must come **before** the worktree is deleted (a local-scope plugin only resolves from its
own directory), needs **`--scope local`** (the default is `user`), and ran **twice** (the worktree
root and its `cone/` each held an install). The five `~/.claude/gsd-core` junctions were removed
with `rmdir`, which does not follow them. Result: no gsd entry anywhere under `~/.claude`
(settings, marketplaces, installed plugins, cache, data, skills); `app-review` untouched; the only
entries not in the pre-trial baseline are `paste-cache/` and `state/`, both Claude Code's own.
`main` has no `.planning/`; the worktree is gone; branch `gsd-trial` remains for plans/97.

**An exception to plans/96's rule** that `main` ends with only the report added: it also gained the
plans/96 record, corrections to two false doc claims the trial exposed (`CLAUDE.md` and
`docs/arch/publicador.md` both said #113 was fixed), and #207's row widened to `Results.jsx`. The
rule existed to keep the *trial* off `main`; none of these are trial artifacts. plans/96 carries two
dated corrections to its own record (step 2b: the trim was manual; step 3: the pin is cwd-relative).
