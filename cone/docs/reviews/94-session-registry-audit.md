## Recommendations (Claude) — suggested order

Grounded against the real prod registry (157 entries, dumped 2026-07-25) and the buckets
below. Every alias VALUE named here was checked to be an exact existing registry entry.

**R1 · Fix two broken cardio aliases (1 line, zero risk) — recovers ~7 occ.**
`ALIASES` maps `'run': 'Corrida'` and `'sprint': 'Corrida'`, but there is **no "Corrida"
entry** in the registry — the real Cardio entry is **"Run"**. So the value is a dangling
pointer: `'run'` still resolves by luck (it hits the "Run" entry *directly*, before the
alias is ever consulted), but `'sprint' → "Corrida" → nothing`, so **"Sprint" ×1 fails**,
and there is no alias at all for the coach's most-common cardio word, **"Corrida" ×6**.
Fix: replace both with `'corrida': 'Run', 'sprint': 'Run'` (alias KEY = the word the coach
types, VALUE = the exact registry name). Worth a one-time sweep of the whole table on the
same rule — **every ALIASES value must be an exact registry entry name**; a dump-vs-ALIASES
check would catch any other danglers.

**R2 · Extend `stripVolumeNoise` — the single biggest lever (bucket 2 = 179 occ ≈ 40% of all misses).**
Bucket 2 is entirely "the movement is fine, a count/distance/rep-scheme is glued to the
front." Today `stripVolumeNoise` only peels a leading bare integer + quote marks
(`^\d+['"’′]*\s*`). Extend it — **match-only**, it never rewrites the coach's text (same
contract as `normExName`) — to also peel a leading:
- **distance** — `800m`, `200m`, `7m`, `30M`, `500m`, `100m` → then re-resolve "Run"/"Row"/"Ski"…
- **duration** — `30"`, `40”`, `1'`, `20''`, `20’`
- **rep-scheme** — `21-15-9`, `20-15-10-5`, `10-8-6-4-2`, `2-4-6-8…`, `8/8`, `15/10`
- **"N cal"** — `12 cal row`, `40 cal bike`

Most of the 179 collapse onto their base movement with **no new registry entries**. Whatever
still misses after stripping feeds R3/R4. Add each new case to `stripVolumeNoise`'s tests.
