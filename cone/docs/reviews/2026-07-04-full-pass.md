## 4 · Architecture & contracts
- 🟡 **NEW — TvController transitively bundles the public Supabase client.** `TvController.jsx:2` imports the SPA client (`../../utils/supabase`), then `TvController.jsx:5` static-imports the slide components from `src/public/tv/TV.jsx`, whose module top-level runs `import { sb } from '../supabaseClient.js'` (`supabaseClient.js:6` calls `createClient` at eval). Both GoTrueClient instances instantiate in one bundle — the exact "never import both clients in the same bundle" hazard CLAUDE.md documents. The 4 slides TvController actually uses don't reference `sb` (only `TV.jsx`'s default export does), so the coupling is needless: moving the shared slides into a client-free module fixes it. Not caught by the invariant's grep because it's a two-hop import. → **new #41**.
- 🟡 **NEW (latent correctness) — TV `loadResults` has no date filter.** `TvController.jsx:100` selects `.eq('session_id', selSessId)` with no `.eq('date', selDate)`; `ClassPanel.jsx:18` `scoreMembers` then `.find`s the first match date-agnostically. Session ids are per-creation uids so it's benign today, but a recurring `session_id` across dates would surface the wrong day's score. → **new #42**.
- ⚪ **Cosmetic render-path divergence**: TV `BlockCard` flattens `Estações` stations into a flat exercise list (`TV.jsx:132-133`) while `Schedule.jsx:508+` renders station structure — display-only, low priority. → note under **#17**.
- ✅ **push() patch-only** — `useTvSync.js:27-34` upserts `{ id:1, ...patch, updated_at }`; every one of the ~20 call sites (TvController / useTimer / useGroupRotation / useClassTracking / GroupsPanel) writes only real `tv_state` columns. No `block_id` misuse (consistently `timer_block_id`); `timer_paused` defined-but-never-written, matching the doc.
- ✅ **3 render paths consistent** (bar the known #17 Schedule-own-markup debt): TV BlockCard + TimerSlide both delegate to shared `ExerciseList`; complex exercises and cardio distance (via `exVolStr`) render identically.
- ✅ **`session.public !== false` filter** correct on all 6 public pages; TvController has zero `.public` references (coach sees all).
- ✅ **Two clients never *directly* cross-imported**; neither hardcodes URL/key (both read `import.meta.env.VITE_SUPABASE_*`). (The transitive breach above is the exception.)
- ✅ **Schema doc ↔ migration in sync**: `0001_init.sql:177-195` defines `tv_state` with exactly the 17 columns CLAUDE.md lists (incl. `timer_paused`, `rotation_*`, `show_qr`, `timer_block_id`). plans/04 landed → migrations are now the source of truth and they agree.
